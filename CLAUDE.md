# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build Commands

```bash
# Configure (pick one)
cmake --preset Debug                # Debug: -O0 -g3
cmake --preset Release              # Release: -Os -g0

# Build (from project root; must configure first)
cmake --build build/Debug
cmake --build build/Release
```

The build uses the `gcc-arm-none-eabi` toolchain (Cortex-M4, hard FPU). CMake generates `compile_commands.json` for clangd indexing.

No test infrastructure exists — this is bare-metal firmware tested on hardware (STM32F407VGT6).

## Architecture

### Layer Stack

```
APP/Tasks/          FreeRTOS tasks (motor control, CAN comms, serial output)
Device/             Custom hardware abstraction (Motor, PID, Filter, Kinematics)
Core/               STM32CubeMX-generated HAL glue (user code in guarded regions)
Drivers/            ST-provided CMSIS + HAL_Driver (untouched)
Middlewares/        FreeRTOS V10.3.1 + CMSIS-RTOS V2 wrapper
```

### Task Model

Five FreeRTOS tasks created in `StartDefaultTask()` (`Core/Src/freertos.c`):

| Task | Priority | Role |
|------|----------|------|
| `vTask_ADC_Sample` | high | Waits on ADC DMA completion semaphore, processes current samples |
| `vTaskCanInfo` | normal | Polls TX queue (10ms timeout), parses chassis speed commands (CAN ID 0x100) |
| `vTaskSeriel` | normal | Consumes serial queue, sends via USART1 DMA, waits for TX-done semaphore |
| `vTaskMotor` | normal | One-shot init: configures motors, PID, ADC DMA, then creates speed control tasks |
| `vTask_SpeedControl` | normal | 100Hz PID speed loop (one instance per motor), reads RPM, runs PID, sends data |

A 10ms software timer (`rpm_read`) fires `vTaskRPM_Read` to sample encoder-based RPM for both motors.

### ISR → Task Data Flow

- **CAN RX**: `CAN1_RX0_IRQHandler` → `HAL_CAN_RxFifo0MsgPendingCallback` → `canRxQueue` (xQueueSendFromISR)
- **CAN TX done**: `CAN1_TX_IRQHandler` → `HAL_CAN_TxMailbox0CompleteCallback` → binary semaphore
- **ADC done**: `ADC_IRQHandler` → `HAL_ADC_ConvCpltCallback` → `xSemaphoreADCReady` (binary semaphore from ISR)
- **UART TX done**: `DMA2_Stream7_IRQHandler` → `HAL_UART_TxCpltCallback` → `xSemaphoreSeriel`
- **Hall sensor**: `TIM4_IRQHandler` / `TIM5_IRQHandler` → `HAL_TIM_IC_CaptureCallback` → `motor_commutating_phase_callback()` (direct, no queue)

### Motor Control (`Device/Src/Motor.c`)

BLDC 6-step trapezoidal commutation via hall sensors. Two motors (`g_Motor1` = TIM1, `g_Motor2` = TIM8), each with a 3-channel PWM bridge (UH/UL, VH/VL, WH/WL). RPM measured from encoder timer (TIM2/TIM3, 1024 PPR) with 10ms sampling. Speed PID wraps `Device/Src/PID.c` (incremental PID with derivative filtering, integral anti-windup, deadband).

### CAN Protocol (`APP/Tasks/TaskCanInfo.h`)

- **RX ID 0x100** (chassis → motor): `[v_linear_mm_s:4][w_angular_mrad_s:4][enable:1][reserved:3]` — little-endian
- **TX ID 0x101** (motor → chassis): status feedback

### Kinematics (`Device/Src/Kinematics.c`)

Differential-drive model. Forward: motor RPM → body velocity. Inverse: body velocity → target motor RPM. Default params: wheel radius 0.075m, track width 0.350m, gear ratio 1.0.

## Code Generation Rules

Files in `Core/` are generated by STM32CubeMX. User code lives between `/* USER CODE BEGIN ... */` and `/* USER CODE END ... */` guards. When regenerating from `motor.ioc`, CubeMX preserves these guarded sections but overwrites everything else. Never place custom logic outside USER CODE guards in Core files.

## Pin Naming Convention

GPIO pins use prefixes: `PM1_` = motor 1, `PM2_` = motor 2. Pin names follow the pattern `PM{1,2}_{HALL,PWM_CTRL}_{U,V,W}{H,L}` as defined in `Core/Inc/main.h`.
